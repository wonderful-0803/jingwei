# ADR-0004：任务累计预算与共享内存账本

日期：2026-09-04。状态：JW-04-a 的实施决策，验证结果另行记录。关联 JW-01、F4.1/F4.2/F4.4/F4.5/F4.9，以及 F6 的预算恢复前置契约。

本 ADR 替代 ADR-0001 中“预算跨恢复是否继承由受信任宿主显式选择”的条款。v0.1 要求累计消耗跨 Turn 和进程恢复保留；宿主只能通过显式、可审计的 grant 追加额度，不能把恢复当作免费重置。JW-04-a 只实现共享内存账本，不因此完成持久化或 AT-F4-04。

## 模块与权限边界

- 预算的纯数据词汇放在 core。新增轻量 `jingwei-budget` crate，负责共享账本、原子预留/结算及活动时长；不执行 IO、不依赖 Tokio，也不新增全局 provider。
- 宿主持有任务预算所有权，任务固定绑定 Task、Session 和 Agent 身份。一次只允许一个 active run，同一账本跨 run 累计消耗；run 内的并行调用使用同一原子账本。
- 宿主上限、Task 累计限额及 run 限额同时约束请求，采用更严格的可用额度；开始新 run 不恢复 Task 已消耗的额度。单调用选项只能继续收紧上限。
- 调用 options 中的 TaskId/StepId 是来源关联，不能作为预算授权、选择另一账本或增加额度的凭证。后续 runtime 绑定负责传递受信任作用域并检查身份。
- 报告是观察数据，不能用于重新创建执行权限、恢复账本或解除冻结。对报告修改数据不会改变账本；读取报告会采样时钟并可能记录停止。`BudgetRun::finish` 成功返回保留 `run: Some(...)` 的报告，其中 `open` 为 false；随后 `TaskBudget::report` 的 `run` 为 None，累计证据继续保留。

## 预留、执行与结算

成功预留是“接受一次受控尝试”的计费边界。一次预留需要原子检查所有适用维度：任一维度不满足时拒绝整个预留，不能部分扣费后返回拒绝。

| 维度或状态 | 本批决策 |
| --- | --- |
| steps、model_requests、tool_calls、corrections | 预留成功立即计费并永久累计。执行前取消也不返还尝试次数；被账本拒绝的预留不收费 |
| 输入/输出 token、工具结果字节 | 先占用变量额度，随后依据结算证据转换为消耗或返还未使用部分 |
| 硬 token 预算 | 仅接受可信的 verified upper bound；估计值不能冒充硬上界，`max_tokens` 参数本身也不是该证明 |
| 实际用量已知 | 记录原始实际值，返还上界内未使用额度。若实际值超过预留或有效限制，保留超出的原值并停止后续准入，不能截断计数掩盖超额 |
| 估计结算 | 按估计值与原预留的较大值保守收费，独立保留 estimated 证据；较小估计不能释放预留 |
| usage 未知 | 将相应变量的全部预留转入 charged，并记录 unknown 次数；已结算预留不继续占 reserved，不能记零或当作已证明未消耗 |
| 明确在 start 前取消 | 允许返还尚未执行的变量预留，保留已消费的尝试次数 |
| start 后取消或执行结果不确定 | 不能走“未执行”返还路径，必须保留实际值或未知额度等结算证据 |
| 未结算 reservation 被 drop | 保留 pending 预留并冻结 Task 后续执行，不能因句柄消失就自动认定未执行、退款或允许重放 |

reservation 不可 Clone，以便明确执行和结算的所有权。start 由受信任执行路径标记；普通关联字段或工具输出不能伪造这个边界。后续调度必须在可能发生上游工作之前标记 start，并为已经接受的记录/执行工作保留所有权。账本不会撤销外部副作用，也不声称计费边界等于 provider 实际计费边界。

本批提供 `TokenBudgetMode::Hard/Soft`。硬预算只接受可信上界证据，不提供未经可信计数支持的精确 token 保证；证据枚举自身不会验证 tokenizer。软预算显式标记估计，模型请求使用估计时输入/输出预留均须大于零，并由有限请求次数和活动时长约束后续准入，不能从未知 usage 推导无限余额。实际执行停止仍由后续 runtime 接入负责。

## 时间口径

- 使用宿主可信、可替换的单调时钟；账本不依赖 Tokio 定时器。注入时钟支持确定性验证，时间回退记录 `ClockMovedBackwards` 并停止准入，不能产生返还额度；时间故障不阻塞既有 reservation 结算和 run 收尾。
- Task 累计各 run 的 active wall time。run 内并行请求的耗时不相加冒充任务活动时长；run 结束后的用户等待不计入活动时长。
- 后续 runtime 必须在 Session/模型 admission 等待之前开始活动计时，使准入等待消耗同一截止时间。JW-04-a 没有接入这些等待路径，不能宣称其已受预算控制。
- 采样间隔中超过有效截止点的部分计入 `cleanup_time`；其他停止发生后，后续采样时间同样计入 cleanup。`active_time` 不越过活动时限，不叠加并行调用耗时。账本没有自动中止机制，这种时间分类不能替代执行取消、排空或清理完成证据；后者在 JW-04-b/c 接入 runtime 时完成。

## 持久化与恢复的后续约束

以下是 JW-04-d 的实现约束，不是本批已经提供的能力：

1. 预算快照须有显式格式版本、Task 绑定身份、revision/CAS 更新语义和规范事件游标；拒绝未知版本、冲突及无法确认的事件引用。
2. 快照只引用确认持久的事件。账本结算、运行报告和 terminal cursor 的关系必须在 Done/Error 封闭 Turn 之前明确，不依赖日志与独立快照的隐含原子双写。
3. 保存累计活动时长与未决 reservation，恢复不能把缺失结果解释为未执行或退款。确认完成的动作不重放，结果不确定的动作保留待核验状态。
4. grant 增额必须受宿主权限控制并记录来源、旧/新限额和关联版本；模型与工具不能修改额度。本批不提供无审计的增额入口。
5. 恢复在新进程、新 Turn 中验证消耗保留。内存报告、共用 Arc 或序列化往返不能作为 AT-F4-04 的通过证据。

完整 Task payload、持久待答状态、Agent/策略兼容校验、工具幂等性和 F6 的全部崩溃窗口继续归 JW-07。

## 本批交付与后续接入

JW-04-a 的边界是 core 词汇、`jingwei-budget` 共享内存账本、只读报告以及针对原子预留、不可退款次数、变量结算、未知用量、drop 冻结、同 Task 单 run 和跨 run 活动时长的验证。实现和检查的实际结果由本批实施记录报告；本 ADR 不表示这些检查已经通过。

JW-04-b 增加有限模型调度；JW-04-c 把受信任预算作用域注入 Agent/Model/Tool runtimes，贯通停止、排空与规范报告；JW-04-d 提供持久化和真正的跨进程预算恢复。无显式 Task 的 Echo/自定义 Agent 兼容入口及其默认有限作用域在 JW-04-c 确定，本批不改变现有调用入口，也不把未绑定解释为已享有有限资源保证。
