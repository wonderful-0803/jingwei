# ADR 0020：本地任务状态的追加链与确认语义

日期：2026-09-14。状态：接受，JW-07-b。前置：[ADR 0019](0019-versioned-task-state.md)。

## 决策

新增独立 jingwei-task-file，采用与既有预算文件存储一致的标准文件锁和 Tokio blocking IO 生命周期。每个任务绑定由宿主供应一个已经持久化的普通文件；适配器不创建、不截断、不替换文件。首次写入建立绑定，后续读取与写入核对完整身份。

选择追加 JSONL 而不是通过临时文件 rename 替换：避免文件锁指向旧 inode、目录同步和锁文件回收带来的另一套协调协议。锁覆盖整条链读取、结构/单调性校验、预期版本比较、追加及 sync_all。该 CAS 对遵循锁协议的写者串行化；不宣称追加具备断电原子性。

存储格式为 version=1、expected_revision 和 checkpoint，快照使用既有 TaskSnapshot 编码。必须从版本 1 连续演进，每条记录按 validate_successor 校验。未知字段/版本、未结束行、身份或兼容性变化、非连续或倒退状态均拒绝，不忽略损坏后缀，也不自动修复。

成功追加并同步返回 Applied；最新的完整相同候选在重新同步后返回 AlreadyPresent。load 也同步完整记录后才确认结果，处理完整 write 后无回执的情形。write/sync 以及后台 worker join 失败返回 Indeterminate；写入前失败返回 DefinitelyNotCommitted。本次确定未提交不覆盖之前的不确定结果。框架错误、Busy、Closed、Corrupt 和 LimitExceeded 保持独立分类。

默认每行 1 MiB（含换行）、日志 64 MiB、单实例 4 个已准入 IO；快照仍受既有 512 KiB 和结构限制。clone 共享计数与关闭状态，单独 open 的实例共享 OS 锁但不共享容量。放弃 future 不撤销 worker；close 禁止新作业并排空所有已接受作业。状态存储锁不授予 Session 或 Task 执行所有权。

## 验证及限制

私有验证覆盖真实文件读写、新进程读取、两个进程 CAS 竞争、锁持有进程退出、取消等待与关闭排空。复用 Linux GNU 系统调用故障夹具：内核文件大小限制产生零字节/部分写入失败，同步边界注入错误，完整写入后退出由新进程重新确认。未模拟电源故障，未据此宣称跨平台或网络文件系统一致性。

规范日志 → 预算检查点 → Task 状态仍是顺序提交，不是三文件事务。记录链不能识别所有外部恶意篡改；宿主在独占执行所有权下继续核对当前规范日志、预算和配置。没有自动轮转、压缩、迁移、工具重放或 Agent 恢复接入；JW-07-c 继续实现受控协调。
