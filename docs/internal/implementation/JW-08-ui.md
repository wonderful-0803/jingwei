# JW-08：Harness 可视化调试工作台

2026-09-14，接续 739fff5。用户希望把黑盒评测改为可手动检查的网页工作台，特别定位 JSON 协议工具说明是否进入模型提示。

内部入口位于 `tests/harness-ui/`，使用 Python 标准库提供本地宿主和静态 HTML/CSS/JS，不新增公共 crate 或前端依赖。三栏布局提供运行历史、任务输入/事件轨迹、请求/事件/状态/预算检查器；支持手动编辑初始/预期状态及写权限、两种协议、步数/输出上限、运行中断、JSON 导出和历史读取。每次测试启动既有 Rust jw-eval，通过真正的 Harness 与 canonical runtimes 执行，无另写 Python Agent 循环。

传输桥分别保留适配器原始 HTTP 请求、实验后发出请求、原始响应。可选合并连续初始 system 消息，另有默认关闭的“将 Schema 同时放入提示词”实验开关；canonical 原事件不被覆盖。附加请求调用模型服务 /apply-template，展示服务返回的诊断渲染，明确不是推理内部 token 捕获。实验额外上下文不在框架预估中，因此不能借此声称框架上下文预算已验证。

启动器可加载用户指定本地 GGUF 到 CUDA0，固定全层 GPU、16K、单并发、温度 0、seed 42、关闭思考。仅绑定回环，启动时检查端口占用；页面写接口验证 Origin/Host/token，模型连接由宿主参数指定。模型及网页服务按需保持运行给用户手动测试，退出启动器时关闭自己的子进程。

## 本次验证

- 三项本地集成测试通过：fake 任务经过 canonical 事件并核验状态、mock HTTP 原请求与实验请求分离、本地访问与无效输入拒绝。
- 浏览器实际打开并检查布局、真实模型任务、实验开关、历史、请求/状态检查器与状态编辑弹窗。
- 真实 Qwen 本地 JSON 请求经工作台成功推理，两次测试都如实显示失败；关闭 Schema 实验时服务端诊断渲染不含工具定义，开启后包含，但模型仍发起错误写入，未宣称修复成功。
- Python/JavaScript 语法与 Git whitespace 检查；没有重复全量框架回归。
