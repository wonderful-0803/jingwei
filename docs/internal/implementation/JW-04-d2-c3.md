# JW-04-d2-c3：实际文件故障与预算验收证据

日期：2026-09-14。开始基线 dev / `ab0221b`；提交身份 wonderful-0803。用户生成的根目录 `pelican-ride.html` 已加入 `.gitignore`，文件保留。

## 交付与修复

生产修复位于 JSONL 精确重试分支：新 provider 直接 `commit_durable` 已存在的完整事件时，现在必须重新执行 sync_data 才能返回 ReplayedExact。先前该分支只比较物理事件，会把上次未确认同步的可见行直接当作成功。重新同步失败会锁存 Indeterminate，直到旧 provider 退出并由新所有者核验。

新增 Linux GNU 私有文件故障夹具，C 源码仅位于 tests/model-protocol/fixtures，测试时用 cc 构建到忽略的 target/storage-faults。LD_PRELOAD 只设置在本测试创建的子进程上，只匹配该夹具临时文件的完整路径；不改变主测试进程环境，不链接到框架，不新增 Cargo 依赖。

- 实际 write 故障：在受控子进程中设置 RLIMIT_FSIZE，内核产生零字节失败或部分写入后的 EFBIG。
- 同步边界注入：在 fsync/fdatasync 之前返回 EIO，或真实同步成功后返回 EIO，验证不可确认与已执行未获回执两种路径。它不是实际介质错误或掉电。
- 进程中断：完整 write 后直接退出，另一个可执行进程重新核验；另补 runtime 在 claim 后及 settle 后的进程终止窗口。
- settle 后的测试通过契约层拒绝最终提交，宿主保存原始 Commit 候选，再验证新进程恢复及重复恢复。其注入层级与实际 syscall 夹具明确区分。

根 workspace 的既有同步失败测试同时加入直接精确重试回归，保护没有 Linux preload 能力的平台。所有平台继续保留其已有文件/运行时测试；GNU/Linux 专属故障测试不会静默跳过缺失编译器或未命中注入，都会明确失败。
