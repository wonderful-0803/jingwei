## 3. JW-04-a：契约与共享预算账本

关联：F4.1、F4.2、F4.4、F4.5、F4.9，及 JW-01/F6 的必要前置契约。

本批执行边界遵循 [ADR-0004：任务累计预算与共享内存账本](../adr/0004-task-budget.md)。它明确替代 ADR-0001 中“预算跨恢复是否继承由宿主选择”的旧表述。当前 PRD 要求累计消耗跨 Turn/重启保留，宿主只能通过显式、可审计的操作追加额度；该持久化要求仍在 JW-04-d 验收。

JW-04-a 只实现共享内存账本，不接入现有 Agent/Model/Tool runtimes，不提供模型调度、持久化、恢复或审计增额入口。以下是本批实施决策，不是已完成或已通过检查的声明：

- core 保存预算数据词汇；新 `jingwei-budget` 轻量 crate 提供共享账本，无 IO/Tokio 依赖，不新增全局 provider。
- Task 固定绑定 Session/Agent，一次仅一个 active run，跨 run 累计。宿主、Task 与 run 限额取更严格约束；run 内的并行调用原子预留，不能并发透支。
- steps/model_requests/tool_calls/corrections 在预留成功时立即计费并永久消耗。输入/输出 token 与工具结果字节先预留再结算；拒绝的预留不产生部分扣费。
- 硬 token 预算只接受可信 verified upper bound。usage 未知时保留相应全部预留并标记 unknown；实际超额保留原值并停止后续准入，不截断或记零。
- reservation 不可 Clone；只有明确在 start 前取消才返还变量预留，不返尝试次数。drop 未结算 reservation 冻结任务并保留 pending，不能自动退款、解冻或重放。
- 可信可替换单调时钟累计各 run 的 active wall time，不叠加并行调用耗时，不计 run 结束后的用户等待。本批验证内存计时；Session/模型准入等待和清理阶段在后续 runtime 接入时贯通。
- 报告只读观察，不是恢复快照或授权凭证。snapshot 版本、revision/CAS、terminal cursor、未决预留重建及审计 grant 仅在 ADR 中约束后续实现，不宣称本批提供。

JW-04-c 再把共享作用域注入 Agent/Model/Tool 绑定并检查关联身份，明确无显式 Task 的 Echo/自定义 Agent 兼容入口和默认有限作用域；不能把本批未接入的调用路径称为已受累计预算限制。

本批交付目标：预算 ADR、core 词汇、共享内存账本和只读报告，及原子预留/结算、取消/drop、同 Task 单 run、跨 run 累计与时间口径验证；指南同步说明适用范围。实际通过情况在实施记录中单独报告。

## 4. JW-04-b：有界模型调度

关联：F4.3、F4.6、F4.7；主要修改 `crates/llm/llm`、`crates/llm/runtime` 和标准组合配置。

- 增加有限执行并发、有限等待容量、明确过载错误和确定性排队规则；首版使用可测试的 FIFO 行为。
- 完整生成和流式生成共用准入路径；在接受时预留容量及预算，拒绝时不调用 provider。
- 区分“上游执行槽”和“已接受但尚未完成记录的总作业容量”。结果持久化阻塞时，收尾作业仍占受控容量，不能只用 semaphore 限制推理而留下无限等待任务。
- 在准入时建立绝对截止时间，排队、请求记录等待和执行共用剩余时限；不能在出队后重新获得完整 timeout。
- 若出队时向适配器传入剩余 timeout，规范记录要区分原始额度与实际传入参数，继续满足记录可核对的要求。
- 排队取消、运行中取消、流消费者丢弃、慢消费者、Turn finish 和 runtime shutdown 都走受拥有的作业收尾路径。
- 保留“请求确认后才调用 provider”“结果确认后才交付成功响应/Finished”的屏障。执行期限到达后禁止新执行；已经接受的持久化操作继续收尾，不能靠丢弃记录 future 伪装完成。
- 时限耗尽或预算停止时，报告执行已停与清理是否完成；清理等待者离开后，runtime 仍保留未结算作业所有权和可观察状态。

交付：有限调度实现，以及并发峰值、队列满、FIFO、排队超时/取消、shutdown、背压和结果写入阻塞等确定性测试。请求大小/排队内存也应有明确支持边界，数量有界不等同于整个进程内存有界。

## 5. JW-04-c：跨模块预算执行与报告

关联：F4.1、F4.2、F4.4–F4.9、AT-F4-03。

调用链扩展为：宿主任务执行句柄 → AgentRuntime → ModelTurnBinding/ToolTurnBinding → 两类 gateway。ActionStep 复用该作用域；自定义 Agent 使用同一组受控入口。宿主直接使用 LlmRuntime.bind_turn、自定义 AgentRuntime 以及后续摘要/修正组件也必须遵循同一预算绑定契约，不能仅修改 canonical AgentRuntime 的调用点。

主要改动：

1. 扩展 Agent 请求/上下文与两类绑定，传递受信任预算和截止时间。关联字段与绑定身份不一致时明确拒绝，不采用调用者提交的另一任务额度。
2. 模型、工具、步骤、修正、摘要等受控工作都经过适用的预算计量；工具继续独立执行 schema/grant/guard/审批，单调用参数只能收紧宿主上限。
3. 区分预算耗尽、超载、排队超时、调用者取消、runtime 停止、语义失败和记录/清理失败；AgentRuntime 统一控制终态，Agent 不能自行制造规范停止证据。
4. 即使 Agent 捕获预算错误并返回 Completed，也要依据 runtime 的预算停止状态产生真实报告；已有副作用和用量不可被吞掉或重试抹除。
5. 报告包含等待时间、模型/工具耗时、调用/修正数、预算预留与消费、token 可信度、停止原因以及清理状态。报告中区分已确认事件和失败时仅保留的未确认尝试证据。
6. 先完成能力排空与所需预算/报告记录，再追加唯一 Done/Error 并 settle。Observer 只作提交后投影，不负责扣减预算；新记录失败要保留类型化失败证据。

交付：跨 Agent/Model/Tool 的闭环、结构化错误和报告、规范事件版本决策、使用教程，以及“不用 ActionStep 也受限”“捕获错误不能绕过”“改变关联字段不能换额度”等集成测试。

## 6. JW-04-d：预算跨 Turn/重启保留与完整验收

关联：AT-F4-01–04、F6.1–F6.3 的预算部分。

- 提供预算快照/重建的最小持久接入，明确日志和快照的写入顺序、版本校验与冲突行为；不能假设两个独立存储原子双写。
- 同一 Task 在 AskUser 后的新 Turn 继续消费剩余额度；新建 gateway、重新绑定 Turn 或重启进程不能自动重置账本。
- 对已记录请求但无确认结果的操作保留不确定状态，采用冻结/核验等保守行为；不重放历史工具，也不凭缺失 usage 退还额度。
- 宿主追加额度须记录操作者来源、旧/新限制及关联版本，模型和工具输出无此权限。
- 用真正的新进程恢复测试验证累计调用、token 未知状态与活动时长；同进程共用 Arc 或快照序列化往返不等于 AT-F4-04 完成。

这一步只交付预算恢复需要的最小能力。业务 Task payload、完整待答状态、Agent/策略兼容验证、工具幂等性和所有崩溃窗口仍在 JW-07 完成；不得据此宣布 F6 整体验收通过。

JW-04 完成门槛：

| 验收 | 必须证明 |
| --- | --- |
| AT-F4-01 | 模型执行和等待数不超上限；收尾积压也受限；并发预算预留不透支 |
| AT-F4-02 | 持续继续动作、缺少 usage、排队超时及取消均有限停止且原因可见 |
| AT-F4-03 | 自定义 Agent、ActionStep 及后续策略扩展通过相同受控入口计量；权限语义不退化 |
| AT-F4-04 | 跨 Turn/进程恢复保留消耗；显式追加额度可审计；未决操作不被当作免费未执行 |
| 既有契约回归 | 请求/结果屏障、唯一终态、消费者丢弃、显式 shutdown 和不确定提交语义保持 |
| 工程与指南 | 两个 workspace 的 fmt/check/test/clippy、默认 facade 检查、rustdoc 和指南片段验证通过 |

每批同步增加针对其语义的测试与指南，不等到 JW-04-d 才开始测试。独立工程使用 `cargo test --manifest-path tests/model-protocol/Cargo.toml`；仅执行主 workspace 测试会漏掉它。
