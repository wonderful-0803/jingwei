# JW-04-d2-c2：Session 所有权与原始预算候选恢复

日期：2026-09-14。分支 dev，开始基线 `5838adc`。提交账户为 wonderful-0803；本批不改变 main、包版本或 tag。契约见 [ADR-0011](../adr/0011-session-ownership-and-budget-recovery.md)，公开指南见[预算候选恢复](../../guide/src/budget-recovery.md)。

## 本批交付

- JSONL 在首次 load/commit 获取 Session 专属的跨进程排他锁，覆盖所有 provider 克隆和后台 IO 的生命周期；历史缓存、正文、报告、终态、settle、最终预算提交都处于同一写者边界。恢复从全新 provider 取得所有权，活跃写者不会被 TTL 或重试抢占。
- load 在排他边界内验证物理日志并同步确认完整内容；同步失败锁存不确定状态，拒绝继续使用。旧 provider 排空且全部释放后才允许交接。
- jingwei-session 提供 SessionRecoveryOwnership 契约；预算核心新增对该既有 crate 的依赖，无第三方依赖变更。JSONL 提供默认 JsonlRecoveryOwnership，存储和路径布局不进入预算核心。
- recover_budget_candidate 仅接收宿主保留的原始最终候选，核对 claim identity/revision、准确规范日志与报告边界；不重建缺失 ID 水位、不退款、不重放模型或工具。原候选已提交则返回 OriginalCommitted。
- V4 原子记录恢复审计与候选，保留原 execution_id/revision、操作身份、来源/理由、所有权 ID、确认游标、候选报告与 ID 水位。相同操作幂等，审计前缀在后续 Turn 和 grant 中保留；每 Task 最多 16 条。
- compare_exchange_guarded 默认拒绝不支持所有权保留的存储。文件适配器将 Arc 移入已接收 blocking worker，取消等待也不提前释放 Session 锁。
- inspect_budget_recovery 只读分类 Ready、无新事件冻结、未确认工作冻结、闭合尾部仍需候选；分类不是授权，也不自动写入审计。

新增测试覆盖：原始候选恢复、已提交原操作核验、恢复提交回执不确定时重试、错误 claim/Session/历史拒绝、审计前缀保护、后续执行和 grant 保留审计、竞争恢复、16 条满额拒绝、同 provider 克隆所有权、真实子进程持锁及退出接管、真实文件 V4 的新进程读取，以及取消已接收文件 IO 后所有权保持至 worker 结束。

指南使用锁定 VitePress 1.6.4 / Vite 6.4.3，构建环境 Node 24.20.0 / npm 11.19.0，满足 package.json engines。根路径和 `/jingwei/` 构建均成功，Markdown 测试通过；每个产物检查 15 页、542 个链接、3 个搜索查询，未包含内部源码。上线状态以提交后的 GitHub Actions 为准，本地验证不等于发布完成。

## 接续边界

这批只交付选定的最终候选恢复，不能视为 F4/F6 完整验收。所有写者必须使用支持锁协议的版本，可信目录中的侧锁不可删除或替换；非合作写者和外部副作用不受该锁保护。shutdown 排空后还需释放所有旧句柄。

缺少候选、未知结果、缺少 ID 水位等状态仍冻结。只读核验结果由宿主按需保存，核心没有通用事故审计库。下一批 d2-c3 聚焦实际 write/sync 系统调用失败和更多 runtime 崩溃窗口，整理 AT-F4-01–04 证据映射；本批进程锁测试和契约层失败注入不能替代完整掉电/存储故障矩阵。完整 Task payload、待答状态与工具幂等恢复继续属于 JW-07。
